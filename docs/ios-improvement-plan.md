## 目標與範圍

先避免原始資料及編輯草稿遺失，再補齊輔助使用與本地化。沿用 `@MainActor @Observable MealStore`、畫面草稿與原生控制項，維持 iOS 17 deployment target 及 Swift 5 語言模式。

本計畫涵蓋本機資料回復、兩個匯入入口、轉盤 Reduce Motion、Dynamic Type 及既有 App 文案遷移。架構改寫、Swift 6 遷移、雲端同步、新增翻譯語言及未經量測的效能優化另行評估。

## 階段 1：資料保護與回復

### 實作工作

- [x] 在 `MealStore` 建立具名載入狀態，區分正常載入、首次建立與既有資料讀取失敗；錯誤提示是否關閉不得改變寫入權限。
- [x] 在共同寫入邊界阻擋讀取失敗狀態下的 `save`、`delete`、`record` 與 `clearHistory`，回傳可供呼叫端處理的失敗結果。
- [x] 顯示持續可到達的回復入口，避免把資料讀取失敗呈現成一般首次使用空狀態。
- [x] 提供重新讀取及保留原始檔案副本的方式；原始檔案無法讀取或備份時，說明原因並維持保護狀態。
- [x] 使用者明確選擇重建資料後，先成功保留原檔副本，再進行原子寫入。備份或寫入失敗時維持回復狀態；重新啟動不得自動覆寫待救援資料。
- [x] 保留一般寫入的「磁碟成功後才更新記憶體」語意，區分讀取失敗與一般儲存失敗。
- [x] 為新提示建立 `Localizable.xcstrings`，納入 App target，確認文案使用可擷取 API。

### 驗收條件

- [x] 損壞檔案載入後，逐一呼叫所有寫入入口，原檔 bytes 均不變；關閉提醒及重新啟動後同樣成立。
- [x] 修復檔案後按重新讀取，清單與紀錄正確恢復，之後才允許寫入。
- [x] 放棄重建不寫入；備份失敗不寫入；明確重建成功後，原檔副本可回讀且內容與原始 bytes 相同。
- [ ] 重建寫入失敗不顯示成功，保留副本及回復入口。模型回傳值與保護狀態已通過檢查，失敗提示的 UI 操作仍待驗收。
- [x] 首次啟動、合法空資料、一般儲存失敗及既有存取／重讀檢查仍通過。

模型檢查確認 bytes、狀態轉換，以及備份與重建寫入失敗。已執行的 UI 流程確認初始讀取錯誤、回復入口、取消、成功重建及重開後副本入口。備份與重建失敗提示的 UI 操作仍待驗收。測試以獨立檔案與測試資料模式執行。

## 階段 2：匯入工作與呈現協調

### 行為決策

兩個入口各自在擁有畫面呈現狀態的範圍管理工作：首頁管理外部 URL，清單庫管理檔案選擇器。每個入口採「最新收到的請求優先」，只保留一份尚未呈現的結果；已顯示的編輯或匯入預覽維持原內容，新的結果等待目前畫面結束。

首頁仍須等待首頁 sheet 關閉且抽選結束；清單庫須等待自己的編輯、分享或預覽 sheet 關閉。清單庫離開時取消其尚未完成的工作並清除待處理狀態。這次不新增多檔匯入佇列。

### 實作工作

- [x] 保存讀取 task 與請求識別；新請求使舊請求及其未呈現結果失效。
- [x] 發布成功或錯誤前，核對請求識別、取消狀態與畫面生命週期；舊請求的錯誤不得覆蓋新請求結果。
- [x] 讀取成功先寫入待處理狀態，經呈現條件判斷後才開預覽，避免直接替換 `sheet`。
- [x] 提供讀取進度及取消入口；取消後即使底層同步協調才完成，也不得再發布結果或錯誤提示。
- [x] 檢查 `Task.detached` 的取消傳遞，在讀取前後與解碼前後檢查取消；保留 security scope 的成對釋放與讀取量限制。
- [x] 提供最小可注入 reader，以便測試指定完成順序；若抽出協調型別，只承擔工作、請求識別與待處理狀態。

### 驗收條件

- [x] A、B 依序請求而 B、A 反序完成時，只有 B 可成為待呈現結果；A 的成功或錯誤都不再影響畫面。
- [ ] 延遲匯入期間新增／編輯清單，輸入草稿後完成讀取，編輯畫面與草稿保持完整；儲存或放棄編輯後才顯示預覽。
- [ ] 取消讀取或離開清單庫後，沒有遲到的預覽、提示或資料寫入。
- [ ] 抽選中、首頁 sheet 開啟及既有預覽開啟時收到外部檔案，均按上述等待規則處理。
- [ ] 預覽取消不寫入；儲存失敗仍停留在預覽；成功後才更新選取清單並關閉。
- [ ] 正常匯入、無效檔案、過大檔案、同名副本、App 內匯入與外部開啟皆有代表性驗證。

以可控制 reader 完成順序的快速測試驗證競態，並將執行入口加入開發說明；另保留實際 `.mealspin` 檔案的 XCTest UI 流程。測試不得只靠固定等待時間製造先後順序。
